## 1. Executive Summary
**Shaheen Interceptor** is a real-time, multi-agent fraud defense platform designed to stop **Authorised Push Payment (APP) Fraud, Vishing (Voice Phishing), and Money Mule Networks** in sub-second latency. 

When a banking customer is manipulated by a scammer on a live call into transferring funds, traditional rule engines fail because the user enters a valid OTP. Shaheen correlates **live conversational coercion signals** with **multi-hop receiver graph telemetry**, intercepts the transfer pre-settlement, deploys an **Active AI Decoy** to bait the scammer into revealing secondary mule accounts, and generates an audit-ready **Suspicious Activity Report (SAR)**.

## 2. Core Multi-Agent Architecture

### Agent 1: Coercion & Vishing Detector (`gemini-2.5-flash`)
* **Input:** Live call transcript / audio stream + transaction metadata (amount, receiver, time).
* **Task:** Detects psychological manipulation tactics (authority impersonation like FIA/Police/Central Bank, extreme urgency, OTP harvesting, screen-sharing requests).
* **Output:** Structured JSON containing `coercion_score` (0–100), `detected_tactics[]`, and exact highlighted quotes.

### Agent 2: Deterministic + Agentic Mule Graph Hunter (Python + Firestore)
* **Input:** Receiver Account ID / IBAN.
* **Task:** Queries Cloud Firestore for 3-hop transaction velocity, circular transfers, smurfing patterns (multiple small inbound transfers followed by immediate crypto/ATM cash-out), and shared device/IP hashes.
* **Output:** `mule_risk_score` (0–100), `graph_nodes[]`, `graph_edges[]`, and anomaly flags.

### Agent 3: Active Decoy & SAR Compliance Agent (`gemini-2.5-flash`)
* **Trigger:** Activated when Combined Risk Score > 80.
* **Task A (Active Decoy Honeypot):** Simulates a believable, confused bank customer in a live chat/voice loop with the scammer ("Transfer failed on this account, send me your backup account/Raast ID") to extract secondary mule accounts.
* **Task B (1-Click SAR Generator):** Drafts a legally compliant Suspicious Activity Report citing timestamps, transcript evidence, device telemetry, and network graph links.

## 3. Data Schema (Cloud Firestore Collections)

1. **`scenarios` (Pre-loaded Synthetic & Benchmark Data)**
   * `id`, `title`, `type` (`VISHING_SCAM` | `MULE_SMURFING` | `CLEAN_URGENT`), `transcript`, `amount`, `sender_id`, `receiver_id`, `device_telemetry`
2. **`active_alerts` (Real-time SOC Stream via `onSnapshot`)**
   * `alert_id`, `timestamp`, `status` (`ANALYZING` | `QUARANTINED` | `CLEARED` | `FROZEN`), `coercion_score`, `mule_risk_score`, `combined_score`, `evidence_chain[]`, `latency_ms`
3. **`mule_graph` (Account Nodes & Transaction Edges)**
   * `nodes`: `[{id, label, account_age_days, risk_level, device_hash}]`
   * `edges`: `[{source, target, amount, timestamp, channel}]`
4. **`decoy_sessions` (Live Honeypot Logs)**
   * `session_id`, `messages[]`, `extracted_iocs` (IBANs, Phone Numbers, Wallet IDs)
5. **`sar_reports` (Generated Compliance Filings)**
   * `report_id`, `alert_id`, `generated_markdown`, `approved_by`, `created_at`

## 4. Backend API Endpoints (FastAPI on Google Cloud Run)

* `GET /api/health` — Health check & GCP service connectivity status.
* `POST /api/analyze-transaction` — Runs parallel Agent 1 (Gemini Coercion Check) + Agent 2 (Firestore Graph Check), writes real-time result to Firestore, and returns combined forensic verdict + latency in ms.
* `POST /api/decoy/chat` — Sends scammer message to Agent 3 (Decoy Agent), extracts any leaked IBAN/account numbers via regex + Gemini, and updates Firestore.
* `POST /api/generate-sar` — Generates structured Regulatory SAR report for a quarantined transaction.
* `POST /api/run-benchmark` — Runs 20 synthetic test cases (15 scams + 5 legitimate urgent transfers like hospital bills) and computes Average Latency (ms), Recall (%), and False Positive Rate (%) for Slide 12.

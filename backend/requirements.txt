# =============================================================================
# SHAHEEN INTERCEPTOR - Pinned production dependencies
# =============================================================================
# Direct packages are pinned with == (no >=, ~=, or floating ranges) so a build
# resolves the same top-level versions everywhere instead of whatever is newest
# at build time.
#
# WHY: unpinned ranges let pip resolve to whatever is newest. For a fraud
# detection system that is a correctness hazard (a new google-genai or
# firebase-admin minor can change auth flow or wire format under you) and a
# reproducibility hazard (the evaluated build stops being the deployed build).
#
# HONEST SCOPE NOTE:
# Only the DIRECT packages are pinned here. Fully locking the transitive tree
# requires capturing a real environment, which was not possible in the audit
# environment (firebase-admin is not installed). To produce a complete lockfile:
#
#     python -m venv .venv && . .venv/Scripts/activate
#     pip install -r requirements.txt
#     pip freeze --all > requirements.lock.txt
#     pip install -r requirements.lock.txt     # verify it installs clean
#
# Then point the Dockerfile at the lockfile. Verified: the pins below were
# written from the package set the app imports, not from a live resolver.
# =============================================================================
